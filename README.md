# Gravitas Campus Platform

One education platform for **Gravitas Campus, Gadag**: programs, interactive lessons, school-lab delivery, contests, a safe AI assistant, website, blog, enrollments and payments.

> **Status:** Phase 1 (Core) complete. See [`docs/02-phase-1-report.md`](docs/02-phase-1-report.md) for what's built and how to test it as each role.

---

## Architecture in one minute

| Layer | Technology | Why |
|---|---|---|
| Web app | Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 | One codebase for website, learner app and admin studio |
| Database | **Plain PostgreSQL** (Supabase today → AWS RDS/Aurora later) | No vendor lock-in: the app talks SQL through `postgres.js` |
| Security | **Row Level Security on every table** + restricted `app_user` role | The database itself refuses unauthorised reads/writes |
| Auth | Own, database-backed sessions; argon2id hashes | Works the same on Supabase or AWS; supports school PIN logins |
| Files | **S3 protocol** (Supabase Storage today → AWS S3 later) | Only environment variables change |
| Email | Provider interface (console in dev, Resend in prod) | Swap providers without code changes |
| Hosting | Vercel (Mumbai) today; `Dockerfile` for AWS ECS/App Runner | `output: "standalone"` build runs anywhere |

**Moving to AWS later** = set `DATABASE_URL` to RDS, run `npm run db:migrate`, set `STORAGE_DRIVER=s3` with AWS keys, deploy the Docker image. No application code changes. Details in [`docs/03-decisions.md`](docs/03-decisions.md).

## Run it locally

**Prerequisites:** Node.js 22+, PostgreSQL 15+ (local install, Docker/Colima, or a Supabase project).

```bash
npm install
cp .env.example .env.local          # then edit DATABASE_URL etc.

# Local Postgres via Colima/Docker (optional):
docker run -d --name gravitas-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=gravitas -p 5432:5432 postgres:16

npm run db:migrate                  # create schema + RLS
npm run db:seed                     # demo data (NEVER in production)
npm run dev                         # http://localhost:3000
```

`npm run db:reset` drops and rebuilds the local database (refuses when `APP_ENV=production`).

## Tests

```bash
npm test            # unit + database tests (RLS, permissions, grading, unlocking, lockout) — needs a local Postgres
npm run test:e2e    # browser tests per role (Playwright; resets & seeds the test DB, runs app on :3100)
npm run lint && npm run typecheck
```

Tests use `.env.test` → database `gravitas_test` on `localhost:5432` (user/password `postgres`). Create it once: `createdb gravitas_test`.
GitHub Actions runs everything on every push (`.github/workflows/ci.yml`).

## Environment variables

Every variable is listed and explained in [`.env.example`](.env.example). Required in production:

| Variable | Example / where to get it |
|---|---|
| `APP_URL` | `https://gravitascampus.in` |
| `APP_ENV` | `production` |
| `DATABASE_URL` | Supabase → Project Settings → Database → **Transaction pooler** URI (port 6543) |
| `DATABASE_SSL` | `true` |
| `SESSION_SECRET`, `HASH_PEPPER` | `openssl rand -base64 48` (different values) |
| `STORAGE_DRIVER=s3`, `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET` | Supabase → Storage → S3 Connection (create a **private** bucket `gravitas-media`) |
| `EMAIL_DRIVER=resend`, `RESEND_API_KEY`, `EMAIL_FROM` | resend.com (verify your domain) |
| `CRON_SECRET` | `openssl rand -hex 32` |

Never commit real values. `.env*` files are git-ignored (except `.env.example` and the non-secret `.env.test`).

## Deploy (Vercel + Supabase)

1. **Supabase:** create the project in region **Mumbai (ap-south-1)**. Apply migrations either with the Supabase CLI (`supabase link` → `supabase db push`) or with `DATABASE_URL=<session-pooler-url> npm run db:migrate`.
   For a *test* project only, load demo data: `npm run db:seed`.
2. **Storage:** create private bucket `gravitas-media`; create S3 access keys.
3. **Vercel:** import the GitHub repo, region `bom1` (already in `vercel.json`), add the environment variables above, deploy. The nightly cleanup cron is configured in `vercel.json`.
4. **Domain:** add your domain in Vercel → Domains; set `APP_URL` to it.
5. **Backups:** Supabase Pro plan gives daily backups (required before launch). Point-in-time recovery is an optional add-on.

### Deploy on AWS (later)
`docker build -t gravitas-campus . && docker run -p 3000:3000 --env-file .env.production gravitas-campus` → push to ECR → run on ECS Fargate / App Runner behind an ALB (health check `/api/health`). Use RDS PostgreSQL (or RDS Proxy) for `DATABASE_URL`, S3 for storage (`S3_ENDPOINT` empty, `S3_FORCE_PATH_STYLE=false`), and EventBridge Scheduler to call `/api/cron/cleanup` with the `CRON_SECRET` bearer token.

## Security notes
- All tables live in schema `app`, which Supabase's auto-generated REST API does not expose.
- Every request runs as the restricted role `app_user` with RLS; privileged code paths (`withSystem`) are limited to login, grading, file checks and jobs.
- Answer keys and hidden tests never reach the browser; the database strips them (`app.learner_lesson`).
- PIN lockout (5 tries → 15 min), password lockout, per-IP rate limits, single-use email links, argon2id hashing, httpOnly cookies, CSRF protection via Server Actions origin checks, security headers, upload type sniffing.
- Full audit log written by database triggers (passwords/PINs never logged).
